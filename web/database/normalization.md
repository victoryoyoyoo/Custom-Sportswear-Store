# 正規化過程

## 0. 未正規化：一張訂單表裝全部

把一張訂單上看得到的東西全部放在同一張表：

| 訂單編號 | 日期 | 顧客編號 | 電子郵件 | 手機 | 縣市 | 付款 | 商品（可能好幾個） |
|---|---|---|---|---|---|---|---|
| O00001 | 2026-03-04 | C001 | user001@example.com | 0918-368-248 | 台中市 | 信用卡 | P08 運動水壺 配件 450 天際藍 #2F6FD6 單一尺寸 ×1；P02 訓練短袖 T 恤 服裝 590 日落橘 #E8671C M ×1；P04 籃球褲 服裝 890 天際藍 #2F6FD6 M ×1 |

問題：「商品」一格放了好幾樣東西，不是單一值。

## 1. 第一正規化（1NF）：每一格只放一個值

把重複的商品拆成多列，每列一個商品，主鍵改成（訂單編號, 項次）：

訂單明細總表（訂單編號, 項次, 日期, 顧客編號, 電子郵件, 手機, 縣市, 付款, 商品編號, 商品名稱, 分類, 價格, 顏色代碼, 顏色名稱, 色碼, 尺寸, 數量）

商品可選的尺寸（S、M、L…）是多值屬性，另外拆一張：

商品尺寸（**商品編號, 尺寸**, 排序）

1NF 仍有三種異常：

- 新增異常：新商品還沒人買，就沒辦法存進這張表。
- 修改異常：顧客換手機，要改他所有訂單的每一列，漏改一列就不一致。
- 刪除異常：刪掉某顧客唯一的一筆訂單，這位顧客的資料也跟著不見。

## 2. 第二正規化（2NF）：去掉部分相依

主鍵是（訂單編號, 項次），但日期、顧客編號、付款、收件資料只跟「訂單編號」有關，屬於部分相依，拆出去：

- 訂單（**訂單編號**, 日期, 顧客編號, 電子郵件, 手機, 縣市, 付款, 收件電話, 收件縣市, 收件地址, 備註, 狀態）
- 訂單明細（**訂單編號, 項次**, 商品編號, 商品名稱, 分類, 價格, 顏色代碼, 顏色名稱, 色碼, 尺寸, 數量）

## 3. 第三正規化（3NF）：去掉遞移相依

- 訂單：訂單編號 → 顧客編號 → 電子郵件、手機、縣市，拆出 **顧客**。
- 訂單明細：商品編號 → 商品名稱、分類、價格，拆出 **商品**；顏色代碼 → 顏色名稱、色碼，拆出 **顏色**。
- 商品：分類編號 → 分類名稱，拆出 **分類**。

## 4. BCNF 檢查

每張表裡，能決定其他欄位的只有主鍵（或候選鍵，例如顧客的 電子郵件），所以全部符合 BCNF。

## 5. 最後的資料表

| 資料表 | 主鍵 | 外鍵 |
|---|---|---|
| 顧客 | 顧客編號 | |
| 訂單 | 訂單編號 | 顧客編號 → 顧客 |
| 訂單明細 | 訂單編號、項次 | 訂單編號 → 訂單、商品編號 → 商品、顏色代碼 → 顏色 |
| 商品 | 商品編號 | 分類編號 → 分類 |
| 商品尺寸 | 商品編號、尺寸 | 商品編號 → 商品 |
| 分類 | 分類編號 | |
| 顏色 | 顏色代碼 | |

## 6. 刻意保留的欄位

- **訂單明細的成交單價**：看起來跟商品的定價重複，但它記的是「下單當時的價格」。商品之後漲價，舊訂單的金額不能跟著變，所以要存。
- **訂單的收件電話、收件縣市、收件地址**：每張訂單可以寄到不同地方，跟顧客基本資料不是同一件事。
- **顧客不存姓名**：顧客只用顧客編號識別，資料是模擬的，不放真人姓名。
- **訂單總金額不存**：用檢視表「訂單金額檢視」即時加總，避免明細改了總額卻沒改。
